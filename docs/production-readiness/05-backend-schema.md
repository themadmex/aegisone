# Backend schema

Use UUID primary keys and UTC timestamptz. Workspace-owned tables carry workspace_id and composite foreign keys of the form (workspace_id, object_id). Add UNIQUE(workspace_id, id) to referenced tables. User identity has separate global scope. Enum values and lifecycle checks are enforced at the database where practical.

| Relation | Key fields and constraints |
|---|---|
| users, sessions, account_tokens | Normalized case-insensitive unique email, password hash, status, MFA credentials, session revocation generation. Tokens store purpose, digest, expiry, consumed_at and user or invited email. Unique secret digests. Encrypt enrolled factor secrets |
| workspaces, memberships, invitations | Workspace name, timezone, active/closing/closed. Membership unique on workspace/user, role owner or contributor, revoked_at. Serialize owner changes under workspace lock and require one active owner. Invite binds exact email, role, actor, expiry and token |
| catalog_questions, catalog_rules, catalog_guidance | Immutable version + stable key. Question order and text, rollup version, gap match, guidance steps and priority. Publish catalog data as versioned releases |
| assessments, answers | Draft/submitted, template and score rules version, revision, score, unsure_count and submitted_at. One draft per workspace by partial unique index. Answers unique per assessment/question and valid for that assessment's template. Include author and updated_at |
| actions, action_evidence, action_events | Unique workspace/action key/source scope, status, priority, guidance version, current reason, current_gap flag, revision. Evidence references immutable assessment/observation with reason and time. Timeline records transition, actor and revision. Reopen only when newly recorded evidence supports recurrence |
| domains, domain_proofs | Unique normalized name per workspace, scope, sends_mail boolean, authority attestation version/actor/time, lifecycle and revocation generation. TXT proof challenge digest, created/expires/verified timestamps and proof generation. Retain only one current proof |
| jobs, observations | Typed verify/check/mail/export/deletion jobs with tenant, actor, operation ID, state, attempts, lease expiry, generation and bounded identifiers. Partial unique active job per domain and kind. Observations unique per job/check kind, normalized status and coarse facts, checked_at and rules version. Keep raw resolver payload out |
| reports | Created_by, created_at, source references, data revision, schema and renderer version, immutable filtered snapshot JSON, revoked_at. Enforce private access on each read and keep printer output local to browser |
| data_requests, export_payloads | Scope, verified requester, state, deadlines, completion timestamps. Export is minimized JSON, separately access-controlled and expires quickly. Closing stops new jobs and invalidates access before deletion |
| audit_events, idempotency_records, usage_counters | Typed actor/action/outcome, scoped reference and time. Audit append-only for app roles. Unique tenant + actor + operation + key with input digest. Quota counters keyed by scope and time window, incremented atomically |

Index tenant/status/time for dashboard queries, tenant/domain/time for observations and queued jobs by available_at. Score, risk action updates and audit commit in one assessment submit transaction. Use row locks or revisions for mutable rows. Assessments and report snapshots remain immutable even if evaluation rules change. Runtime account e-mail routes and identity bootstrap read only narrow global tables.

Enable and force row-level security on tenant data. The web role has no table ownership or BYPASSRLS. Application services verify membership and use transaction-local tenant scope derived from that authorization. Initialize scope through a minimal current-user membership lookup design, with no general membership enumeration. Reject unset contexts, and test pooled-connection reuse. The queue runner claims only a narrow job pointer through a reviewed, least-privilege database interface and rechecks tenant, role, proof generation and job lease before work and on completion. No worker uses a general-purpose bypass role. Release tests must cover the bootstrap, claimant and all cross-tenant references. [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)

## Data lifecycle

Private PostgreSQL stores identities and posture. The email relay gets delivery fields only and the DNS resolver sees queried names only. Encrypted backups live in a restricted storage account. Proposed retention is until workspace closure for assessment/action history, 90 days for domain observations, 180 days for content-free audit, 30 days for operational logs, seven days for exports and 30 days for backups. Clean up unfinished proofs, expired invitations and short-lived job artifacts automatically. Reports retain their copied historical observations until revocation/closure and disclose this to users. Purge revoked report payloads and closed data from live storage within 30 days, subject to reviewed obligations. Keep a restricted deletion ledger outside the recovery set and replay before opening a restored system. Verify effective deletion across processors and exports.

Run forward, reviewed, repeatable migrations with a separate migration role. Use expand-contract for live changes. Rehearse a production-sized representative backup, isolated point-in-time restore or snapshot restore, integrity checks and scoped tenant restore to a temporary environment.
